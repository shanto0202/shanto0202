## 🧠 How I Like to Work

- **Understand before implementing** — a crisp problem statement saves more time than a clever patch.
- **Make invalid states difficult** — validation and clear boundaries belong in the design, not as afterthoughts.
- **Prefer proof over assumption** — tests, measurements, and small experiments guide decisions.
- **Keep the next developer in mind** — readable code and useful documentation are part of the product.
- **Stay curious** — every project should leave the toolbox larger than it found it.
